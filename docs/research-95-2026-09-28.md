# Research toward 95% and comparison-source correction

The fixed development corpus reached **93.427%**, 251,247 / 268,923, from 93.372%. This cycle recovered 149 listings and lost zero matches across all five scenarios. First-candidate agreement remains 84.722%. The 95% target is **not met**; 4,230 additional development matches are needed.

## What the benchmark actually compares

The downloader reads `MLSLISTINGADDRESS` as the input and ATTOM `PROPERTYADDRESSHOUSENUMBER`, `PROPERTYADDRESSSTREET*`, and `PROPERTYADDRESSUNIT*` as the expected components. This mapping is visible in `scripts/download-geographic-corpus.py`. A read-only query of the live HomeAnalytics MotherDuck schema confirmed it. That table does not expose native MLS house/street/unit component fields. A broader metadata search found no columns with standard MLS component names in the current HomeAnalytics catalog.

The earlier label "MLS field agreement" was imprecise. This is **MLS → ATTOM field agreement**, a cross-source comparison. ATTOM property fields are not independent component annotations for the MLS listing text. They can omit a listed unit, normalize an identifier differently, or assign a directional differently. Corpus admission verifies lexical evidence and does not resolve all these role differences.

On the same admitted population, the recorded property-address string agrees with those property fields on 268,666 / 268,923 cases, 99.904%. This is a separate diagnostic scenario, not a replacement for the 95% target or a national parser-accuracy claim.

The dashboard now labels the comparison source explicitly and shows the new 95% goal, including on historical holdout evidence. Historical run targets and scores remain intact. The corpus, admission policy, comparison normalization, denominator, and split membership did not change.

## Changes retained

- Combine duplicate suffix repairs with independently observed repeated directional, house-number, or secondary evidence.
- Recognize repeated postdirectionals without removing explicitly designated or different units.
- Join observed initials in a parsed street name, preserving the original reading.
- Offer bounded route-prefix hyphens and numeric-letter route identifier punctuation variants. Numeric ranges and primary house-number hyphens remain intact.

These are alternatives, not registered-address corrections. They preserve the literal readings and remain subject to the existing candidate budget. The optional spelling mode disables the new spelling alternatives. Repeated-field structural repairs work in both modes.

The tests first reproduced missing interpretations on small synthetic examples. The complete package gate passed 433 tests, type checking, ESM/CommonJS builds, and packed JavaScript/TypeScript consumers. All five corpus scenarios had zero any-candidate and first-candidate agreement regressions.

Mean candidate count rose from 2.396 to 2.444, about 2%. In the paired local benchmark, median parsing time rose from 231.7 ms to 244.8 ms on 16,808 inputs, about 5.6%. Timings vary and cannot be compared directly with prior sessions.

## Remaining failure evidence

The starting failure set contains 17,825 listings. Disjoint closest-candidate patterns include 2,995 cases whose only disagreement is an empty expected unit, 1,675 with an empty expected suffix, 1,643 with an empty expected predirectional, 556 with an empty expected postdirectional, and 2,013 involving both directional roles. These are diagnostic signals, not 8,882 independently proven annotation errors. They were not used to exclude additional records.

The structural audit found only about 60 recoverable cases from combined duplicate-field repairs. A separate spelling and format audit found modest additional opportunities. Many other possible score increases would require dropping observed units/directionals, selecting one endpoint of an address range, or treating a differently formatted identifier as the same entity. Those changes need reference evidence or separately adjudicated labels.

Primary number hyphens deserve particular care. [USPS Publication 28 Appendix D1](https://pe.usps.com/text/pub28/28apd_002.htm) describes regional hyphenated address forms and says to retain a hyphen when it matches the ZIP+4 reference. The parser has no such reference. Route spelling rules were checked against [Appendix F](https://pe.usps.com/text/pub28/28apf.htm). Neither source justifies deleting meaningful address components to reproduce an inconsistent property record.

Reaching 95% parser correctness requires trustworthy labels for the same input text. Continuing to target 95% cross-source agreement is a different objective, potentially involving the future reference-backed service. This cycle establishes neither that 95% cross-source agreement is impossible nor that all remaining cases are parser errors.
