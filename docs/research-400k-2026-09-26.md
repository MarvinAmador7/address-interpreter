# Parser research on 400,000 MLS addresses

The fresh holdout reached **79.523% strict MLS field agreement**, compared with 78.158% for the build at the start of this research. The geographic cohort reached 80.842%; the difficult-format cohort reached 75.607%. The combined 80% target remains unmet. These results measure candidate recall against source fields, not unique address matching or postal validation.

This work is parser-only. The library makes no network calls and contains no reference address database. The existing resolver interface still requires a caller-supplied index. A future reference-backed cloud service is outside this change.

## Corpus and evaluation

The live download used the HomeAnalytics MotherDuck table `homeanalytics.raw.attom_listing_analytics_complete`. It saved 400,000 properties with address fields, county metadata, and hashed property groups. It contains 300,000 county-balanced geographic rows and 100,000 separately sampled difficult-format rows. Coverage includes all 50 states plus DC and 3,237 source county groups. County groups use a five-digit source FIPS when available and county text otherwise; that count is not a verified inventory of distinct official counties.

The query sampled 5% of source blocks with seed 20260927, selected one listing per property, excluded the earlier corpus's property groups, and balanced geographic rows by county and challenge rows by address category. No remote writes occurred. The download has no duplicate property groups or property-group overlap with the earlier corpus. It is not population weighted or a random national address-accuracy sample. Source changes and block sampling can change a future download; the saved corpus and its hash freeze this evaluation.

The property hash assigned 319,932 records to development and 80,068 to holdout. A pre-evaluation audit found 247 complete address keys shared across those splits despite different property IDs. The holdout preparation script then excluded exact normalized structured-address and raw listing/locality keys already seen in the earlier corpus or new development data, plus duplicates within the holdout. It removed 312 rows by structured key and another 203 by listing/locality key, leaving **79,553 holdout rows**. Selection used no parser output or score. Exact-key deduplication does not establish that every remaining row represents a different physical address; aliases and shared buildings remain possible.

Records without reference house/street fields are excluded by the unchanged evaluator. The fresh holdout has 78,529 eligible property/generated cases and 78,528 eligible raw-listing cases. One otherwise eligible listing string is missing. The original 20,214-row stress corpus remains a separate benchmark with 4,033 eligible held-out cases.

Expected house number, street name, suffix, both directionals, and unit must all agree in one candidate. The suffix reference, case/whitespace normalization, and comparison fields were unchanged. Generated cases are formatting checks constructed from structured fields. Their much higher scores must not be described as raw MLS parsing accuracy. No holdout address-level failures were inspected. The parser was frozen before the fresh holdout was scored; the older stress holdout is a repeated aggregate comparison.

## Development research

| Accepted stage | Original stress development | Expanded development |
| --- | ---: | ---: |
| Starting build | 11,781 / 73.320% | 245,571 / 77.918% |
| Compound units, spelling and floor formats | 11,906 / 74.098% | 247,618 / 78.568% |
| Repetition, embedded units and route ordering | 12,076 / 75.156% | 248,944 / 78.989% |
| Numbered names, repeated identifiers and separators | 12,146 / 75.591% | 249,687 / 79.224% |
| Leading secondary phrases and tower chains | 12,148 / 75.604% | 249,694 / 79.227% |

The denominators are 16,068 and 315,164. Final development gained 367 matches on the original stress set and 4,123 on the expanded corpus over the starting build, without losing a previous match in any scenario. The final expanded run still needs 2,438 more development matches to reach 80% and exits with status 2.

The research loop caught two vocabulary regressions before holdout. An informal `SP` marker incorrectly rejected a literal terminal name token, and adding `Tower` as a marker consumed street names such as `Water Tower Road`. Both now preserve their literal readings. A seeded invariant also exposed a punctuation-only street name after extracting directionals; such candidates are rejected. Floor-separator spans now include their separating hyphen instead of leaving it unaccounted for.

Implemented formats include:

- Compound identifiers such as `3-204`, retaining the opaque identifier alongside a building `3`, unit `204` reading. Explicit building/unit chains are not split again. The inferred chain has individual spans within the observed token.
- Ordinal floor chains, informal `Flr` and `SP`, and separators before secondary phrases.
- Towers within explicit chains and secondary phrases before the house number, such as `Apt 4 123 Main St`.
- Numbered-street spelling alternatives, saint/mount/fort and avenue abbreviations, surname spacing, apostrophes, compact highway prefixes, and `Old Hwy` forms.
- Repeated equivalent directionals and identifiers, embedded short unit identifiers, alphanumeric unit punctuation, whole-building labels, and separated fractional house numbers.

The original interpretation stays available when it parses. Assumptions identify uncertain readings. A matching service must check complete secondary chains and treat candidate order as unranked. In particular, `secondary` remains the last component in input order; it is not necessarily the apartment. Numbered street names have registered spellings, so alternatives do not assert a preferred spelling. See [USPS section 235](https://pe.usps.com/text/pub28/28c2_016.htm) and [Appendix F](https://pe.usps.com/text/pub28/28apf.htm).

## What remains

On the expanded development set, the largest final failure groups are suffix-only, 21,390 cases; unit-only, 10,207; street-name-only, 6,353; and street name plus suffix, 4,939. These are differences for the closest candidate, not adjudicated parser errors.

A lexical evidence audit of the preceding accepted development run found 19,695 suffix-only failures with no token corresponding to the expected suffix, using the independent suffix aliases. It found 6,376 unit-only failures without the literal expected identifier and 3,233 unit-only failures whose reference unit is blank. The unit check can miss compact formatting or aliases; these counts are diagnostics, not a proven accuracy ceiling.

Some source fields omit observed information, supply information absent from the listing, or place a directional on the other side of the street. The parser does not fabricate missing suffixes or units, remove significant house-number hyphens, exchange pre/post directionals just to match a label, or discard an observed distinct unit. Such changes could increase source agreement while reducing address identity safety.

Further research should distinguish annotation problems from recoverable grammar on development examples. Useful remaining parser topics include named secondary identifiers versus numberless designators, address lists/ranges with explicit multiple destinations, and descriptive text around a delivery line. These need defined output contracts and adjudicated examples. Arbitrary street-name corrections and address aliases belong with the separate reference-backed service. This benchmark does not prove that 80% is impossible, and this work does not claim that it has been reached overall.

## Repeating the loop

`npm run research -- --input .local/corpus/mls-geographic.jsonl --baseline <previous-accepted-build.mjs> --target 80` runs the package checks, development comparison, regression gate and failure grouping. It writes an individual run record and appends a history journal. Checks and evaluation failures are recorded too. Source/test, corpus, evaluator/reference, and baseline hashes identify the inputs.

Exit 0 means the development threshold passed with no regression, exit 1 means a check or regression failed, and exit 2 means research must continue. An agent or developer implements hypotheses between cycles. There is no background code-writing process. Holdout evaluation is a separate command, so development iterations do not inspect its examples.

Tracked tools are `scripts/download-geographic-corpus.py`, `scripts/prepare-holdout.mjs`, `scripts/research-cycle.mjs`, and `scripts/evaluate-corpus.mjs`. The downloader accepts 300,000 to 500,000 rows and refuses to overwrite a frozen output. The holdout selector also refuses to overwrite its output. All address-level artifacts stay under ignored `.local/`; the package allowlist excludes them.

The harness now generates an interactive `.local/research/index.html` at startup and completion. It plots score progression and the tradeoff between recall and candidate count, with corpus/cohort/measurement controls, selectable experiment details, field-difference bars, and an experiment log. Failed cycles stay unscored; rejected builds remain visible. Holdout markers are separate from development lines. `npm run research:report` regenerates it without evaluating addresses. Optional `--label` and `--note` arguments describe new cycles. The existing report includes 16 historical cycles/checkpoints through the fresh holdout, assembled from aggregate evaluation files without changing those results.

The report is standalone HTML with no network assets or source address examples. Four additional tests verify aggregate-only projection, unscored failures, baseline provenance and safe JSON embedding, bringing the full test count to 296. Browser checks cover both chart modes, all five measurements, both corpora, cohort filters, keyboard selection, holdout visibility and a narrow viewport.
